# Чек-лист cutover миграции DWH

Документ не заменяет план проекта, а фиксирует то, что обычно забывают в ночь
переключения. Отмечать в трекере, не здесь.

## До миграции (T-10 … T-1)

- [ ] Инвентаризация: все потребители старого DWH найдены, у каждого есть владелец
      и подтверждённая дата переключения.
- [ ] Спецификации сверки (`specs/*.json`) покрывают 100% таблиц, которые читают
      потребители; для остальных зафиксировано решение «не мигрируем».
- [ ] Известные и принятые расхождения описаны явно: таблица, причина, кто
      подтвердил. «Похоже, это ок» — не подтверждение.
- [ ] Суррогатные ключи и SCD2-версии сверены отдельно: `customer_key` в новом
      DWH не обязан совпадать, обязан совпадать бизнес-ключ и атрибуты на дату.
- [ ] Проверены права: сервисные аккаунты потребителей существуют в новом DWH.
- [ ] Прогон parity на полном объёме завершён, отчёт приложен к релизу.
- [ ] Замерено время полного прогона сверки — оно определяет длину окна cutover.
- [ ] Есть план отката: старый DWH остаётся доступным только на чтение N дней,
      запись в него прекращается в момент T0.

## Ночь переключения (T0)

- [ ] Запись в старый DWH остановлена (или переведена в read-only).
- [ ] Финальная инкрементальная загрузка в новый DWH выполнена.
- [ ] Parity прогнан повторно; exit code 0. Ненулевой код — стоп, не «посмотрим утром».
- [ ] DQ-гейт на новом DWH зелёный (`failed = 0`, свежесть в норме).
- [ ] Потребители переключены по одному, с проверкой ключевой метрики каждого.
- [ ] Сверены контрольные суммы отчётов, которые смотрят финансы.

## Первые сутки (T+1)

- [ ] Ночной батч прошёл по расписанию и без ручных вмешательств.
- [ ] Свежесть витрин в норме (`dq_seconds_since_last_run`), алерты не горят.
- [ ] Расхождения, найденные потребителями, заведены как задачи с владельцем.
- [ ] Стоимость и длительность батча сравнены с прогнозом; отклонение > 20%
      разобрано.
- [ ] Принято решение по старому DWH: архив / удаление / продление read-only.

## Через неделю (T+7)

- [ ] Parity прогнан ещё раз на новом объёме (миграция данных ≠ миграция процесса:
      важно, что новые данные тоже сходятся).
- [ ] Известные расхождения либо закрыты, либо переведены в «принято навсегда».
- [ ] Runbook обновлён: как перезапустить батч, как откатить партицию, кого будить.
- [ ] Ретроспектива: что в плане оказалось неверным, что добавить в чек-лист.
