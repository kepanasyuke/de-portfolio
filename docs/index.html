01 · Batch DWH

Landing → bronze → DDS → DM

Ночной пайплайн: сырая выгрузка в озеро, типизация через try_cast, карантин плохих строк, upsert в 3NF и звезда Кимбалла с SCD2.

  • Идемпотентность на всех слоях: перезапуск за ту же дату даёт то же состояние
  • Карантин вместо падения джобы: контракт источника видно по метрике
  • SCD2 под защитой частичного уникального индекса
  • SMART окно в факте: правки приезжают, история не переписывается
README SQL merge DAG
02 · Streaming

Kafka → Spark Structured Streaming

Жизненный цикл заказа как поток событий: партиционирование по order_id, watermark, дедупликация в два слоя и компакция в DDS каждые 15 минут.

  • Exactly-once на практике: чекпоинты + PK в DWH
  • Валидация переходов там, где видна вся история заказа — в DWH
  • Деньги в Decimal, ни одного float в модели события
  • Один код для стрима и backfill через availableNow
README Контракт Merge
03 · Data Quality

YAML-правила → SQL → гейт и метрики

Свой движок проверок: правило компилируется в один SELECT с двумя колонками-счётчиками, результат идёт в meta.dq_result, оттуда — в Prometheus.

  • 8 типов проверок, включая freshness и произвольный expression
  • Безопасность: валидация идентификаторов, запрет ; и комментариев
  • Гейт настраивается по строгости: error / warn / none
  • Экспортёр метрик и готовый Grafana-дашборд
README checks.py rules.yml
04 · ClickHouse

Витрины и измеренный бенчмарк

Колоночная модель поверх того же факта: ReplacingMergeTree, пред-агрегат на AggregatingMergeTree и скрипт, который мерит каждое решение вместо пересказа туториалов.

  • PREWHERE vs WHERE, uniqCombined vs uniqExact
  • FINAL vs argMax — цена гарантии актуальности
  • Партиции по месяцу, LowCardinality, ZSTD
  • Медиана нескольких прогонов, серверное время
README DDL Бенчмарк
05 · Миграция

Реконсиляция старого и нового DWH

Как доказать, что миграция не потеряла данные, не вычитывая миллиарды строк: подпись по бакетам, diff по ключам, diff по колонкам — и exit-код как cutover-гейт.

  • Бакеты по hashtext/cityHash64: агрегат вместо полного чтения
  • Канонизация: 199.90 = 199.9, пустая строка = NULL, naive = UTC
  • Допуск 1e-6 для чисел, ignore для технических колонок
  • Чек-лист cutover: T-10 → T0 → T+1 → T+7
README Движок Чек-лист
06 · Игра

«Труба пайплайна»

Сеточная головоломка: поворачивай модули кликом и доведи чистые записи до витрины, а грязные уведи через Clean в карантин. Пока труба дырявая, записи стоят в тупике и теряются.

  • Топология важнее скорости: без соединения поток не идёт вообще
  • Clean — это DQ: грязная уходит вбок, забыл повернуть — протечка в DWH
  • Backpressure: тупик держит запись 2.5 с, потом она в потерях
  • Уровни проверены солвером: tests/test_levels.py
